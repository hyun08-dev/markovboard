# MarkovBoard

부루마불의 규칙을 **유한 마르코프 연쇄**로 형식화하고, 전이행렬 $P$ 의 정상상태 분포
$\pi$ 를 계산해 각 칸의 장기 방문 확률 · 기대수익 · 첫 도달 확률을 분석한다.
그 결과로 플레이어 커뮤니티의 정량적 통설들을 판정한다.

```
게임 규칙 → 상태공간 → 전이행렬 P → π, v → 수렴 분석 → 시뮬레이션 검증 → 시각화
```

## 주요 결과

| 질문 | 답 |
|---|---|
| 가장 오래 머무는 칸은? | **무인도 10.835%** (균등의 4.33배). 그런데 그중 **67.8%가 체류**이고 유입은 3.49%뿐이다 — "잘 들어가서"가 아니라 "못 나와서"다 |
| "부에노스아이레스는 7의 배수라 효자땅"? | **기각.** 정상상태에서 21번(2.256%)은 이웃 19·23번보다 오히려 낮다. 효과는 k=1~4의 과도상태에만 있다 |
| 우주여행은 어디로 가야 하나? | **무인도 도피가 턴당 기대 지출을 8.8% 낮춘다.** "뉴욕 우선"은 이 지표로는 오히려 2.3% 손해 |
| 방문 확률까지 곱한 투자 회수 1위는? | **서울 6.161%/턴** (회수 16.2턴). 뉴욕·런던은 통행료가 최고급인데도 하위 |
| 월급은 얼마나 자주 받나? | **24.018%** — 근사 8.4/40 = 21%보다 **높다** (계획서 예상과 반대) |
| $\|\lambda_2\|$ 는? | **0.70398**, 복소 켤레쌍 $0.22137 \pm 0.66826i$ |

전체 12개 실험은 [`docs/experiments.md`](docs/experiments.md).

## 검증

같은 답을 **서로 계산 경로가 없는 방법들**로 구해 맞춘다.

| 축 | 방법 | 결과 |
|---|---|---|
| 1 | 멱승법 해석해 | 잔차 ‖πP−π‖₁ = 6.5 × 10⁻¹⁵ |
| 2 | 몬테카를로 (400체인 × 1800턴) | 40칸 중 38칸이 95% 구간 안 (기대값 38) |
| 3 | Kac 보조정리 $m_{ii} = 1/\pi_i$ | 43상태 최대 상대오차 2.4 × 10⁻¹⁴ |
| 4 | 파이썬 독립 구현 | 전이행렬 차이 2.2 × 10⁻¹⁶ |
| 5 | 해석적 정답 (순수 순환 보드) | $\pi_i = 1/40$ 이 소수 15자리까지 |
| 6 | 손계산 (4상태 축소 모델) | $\pi = (1/6, 1/2, 1/3)$, $\|\lambda_2\| = 1/2$ |

## 원칙

- **선형대수와 확률 계산은 전부 직접 구현한다.** 멱승법 · 디플레이션 · 가우스 소거 ·
  난수 발생기까지. 라이브러리는 렌더링(React)과 차트(Recharts)에만 쓴다.
- 계산 코드(`src/markov/`)는 화면에 의존하지 않는 순수 함수로 유지한다.
- 규칙 해석은 데이터가 아니라 설정(`config.ts`)으로 전환한다 — **설정 하나가 실험 하나.**
- 가정을 밝히면 틀린 것이 아니라 정의한 것이 된다. 모든 해석은 `docs/assumptions.md` 에.

## 배포

정적 사이트라 **GitHub Pages 와 Vercel 어느 쪽으로도** 올릴 수 있다.
`base: './'` 로 빌드하므로 루트든 하위 경로든 같은 산출물이 그대로 동작한다.

GitHub Pages 는 `.github/workflows/deploy.yml` 이 준비되어 있다 — **기본 브랜치에
푸시하면 Pages 활성화까지 워크플로가 알아서 한다.** 권한이 없어 자동 활성화가
실패하면 저장소 **Settings → Pages → Source** 를 `GitHub Actions` 로 한 번만 바꾸면
된다. 타입 검사와 테스트를 통과해야 배포된다. 자세한 내용은 [`docs/deploy.md`](docs/deploy.md).

## 모델 한 줄 요약

> 자산·소유권·건설·파산 동역학을 제외하고 **말 한 개의 위치 과정만을** 마르코프
> 연쇄로 모델링한다. 따라서 $\pi$ 는 "게임의 정상상태"가 아니라 **"위치 과정의
> 정상상태"** 다.

한 스텝은 **한 플레이어의 완전한 턴**이다. 무인도 대기가 턴 단위로 규정되어 있기
때문이다. 그 대가로 통행료는 $\pi$ 가 아니라 **한 턴당 착지 기대 횟수 $v$** 로 계산한다.
