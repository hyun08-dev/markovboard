# 개발 일지

커밋 메시지와 함께 **어떤 수학적 판단을 거쳐 현재 모델에 도달했는지**를 남긴다.
완성된 코드만이 아니라 버린 접근과 수정 과정도 기록한다. (계획서 §13)

## Phase 0 — 스캐폴딩

Vite + React + TypeScript + Vitest 로 프로젝트를 세웠다.
계획서 §7의 원칙에 따라 **선형대수와 확률 계산은 전부 직접 구현**하고, 라이브러리는
렌더링(React)과 차트(Recharts)에만 쓴다. 상태가 43개 규모라 브라우저에서 즉시
계산되므로 WebAssembly나 Web Worker는 두지 않는다.

`tsconfig` 에 `noUncheckedIndexedAccess` 를 켰다. 행렬을 배열의 배열로 다루는 코드에서
인덱스 실수를 컴파일 단계에서 잡기 위해서다 (계획서 §7의 TypeScript 채택 이유).

## Phase 1 — 보드·카드 데이터

`board.ts` 는 순수 데이터 배열, `rules.ts`/`transition.ts` 는 효과 함수로 분리했다.
규칙을 데이터에 하드코딩하면 모델 변형 실험마다 코드를 고쳐야 하기 때문이다 (§8).

**발견한 자료 불일치 두 건:**

1. 계획서 §5.1 카드 분류표의 합이 31장으로, 덱 총 장수 30장과 어긋난다.
   이동 카드 13장은 §5.2에 개별 열거되어 있으므로 비이동 카드를 17장으로 맞추었다.
   위치 과정에는 영향이 없다 (12/30 = 40% 불변). → `docs/card-table.md`
2. 베른·베를린·오타와 빌딩료가 자료마다 다르다. 기본 시나리오가 호텔 1채라
   기본 결과에는 영향이 없어 미입력으로 두었다. → `docs/board-table.md`

**막힌 지점:** 나무위키 대조 자료를 자동으로 읽으려 했으나 개발 환경의 네트워크 정책이
namu.wiki 를 차단했다 (egress proxy 403). 우회하지 않고 자료 사본을 직접 전달받았다.

## Phase 1-b — 자료 대조와 데이터 확정

전달받은 문서(「주요 카드」·「게임 방법」·「모노폴리와의 차이점」 사본)를 읽고 대조했다.
**계획서를 그대로 옮기지 않고 원자료와 맞춰 본 것이 이 단계의 핵심이다.**

### 확정한 것

1. **§4.3 불일치 세 건이 모두 문서 B로 확정.** 베른·베를린 빌딩 통행료 55만,
   오타와 60만.
2. **통행료 전체 표 입수.** 대지료 · 별장 1채 · 별장 2채 · 빌딩 · 호텔의 다섯 단계.
   대지료가 만 원 미만(타이베이 2천 원)이라 금액 단위를 만 원 소수로 확장했다.
3. **건축비는 누적하지 않는다.** 부루마불은 건물 종류를 골라 짓는 구조라 호텔만
   지으면 호텔 건축비만 든다. `buildCostMode` 설정은 불필요해져 삭제했다.
   — 미확정 항목 B1 해소.
4. **우주여행 칸은 더블과 무관하게 턴을 끝낸다.** 전이행렬의 더블 재귀를 끊는
   조건이므로 `spaceEndsTurn` 설정으로 남겼다.

### 계획서를 바로잡은 것

**우주여행 초대권은 대형판에서 1장이다.** 자료가 "퀸 엘리자베스 호가 있는 버전에서는
1장, 없는 버전에서는 2장이며 대신 유람선이 없다"고 명시한다. 계획서 §5.2는 우주여행
2장과 유람선 1장을 함께 실어 **두 버전을 섞었다.**

이를 바로잡자 계획서 §5.1 분류표의 합계 불일치(13+7+6+5 = 31 ≠ 30)가 저절로 풀렸다.
이동이 12장이면 정확히 30장이 된다. 두 오류가 같은 원인에서 나온 것이었다.

결과로 **위치 변경 카드가 12장이 아니라 11장**이 되어

$$P(\text{황금열쇠에서 위치 변경}) = 11/30 \approx 36.67\%$$

계획서의 40%는 잘못된 값이다. 이 차이는 실험 8(무인도·서울 유입 경로 분해)에
직접 들어간다.

### 검증을 자료 본문과 맞물리게 했다

표를 옮길 때 가장 위험한 것은 조용한 오타다. 그래서 자료 **본문의 서술값**을 테스트로
박아 두었다.

- "타이베이 풀하우스 37만" → `tollOf(타이베이, 'full') === 3 + 9 + 25`
- "뉴욕 풀하우스 반액대매출 117만 5천" → `investmentOf(뉴욕, 'full') / 2 === 117.5`

표의 숫자를 하나라도 잘못 옮기면 이 두 테스트가 깨진다. 표와 본문이라는 **서로 다른
경로의 두 값이 맞물리는지**를 확인하는 장치다.

### 근사로 남긴 것

'무인도 탈출권(무전기)'은 엄밀히는 무인도 대기 턴을 줄인다. 소지 여부를 상태에 넣으면
상태공간이 두 배가 되므로 넣지 않았다. 한계로 기록한다.

## Phase 2 — 4상태 축소 모델 교차 검증

큰 모델에서 답이 틀리면 **어디가 틀렸는지 알 수 없다.** 그래서 손으로 풀 수 있는
크기의 보드를 먼저 만들었다.

장난감 보드를 아무렇게나 고르지 않았다. 4칸 순환 보드에 주사위만 굴리면 $P$ 가
이중확률행렬이 되어 $\pi$ 가 균등분포로 나오는데, 그러면 **틀린 구현도 통과한다.**
그래서 "3번에 착지하면 1번으로 끌려간다"는 강제 이동을 하나 넣었다. 그 결과

- $\pi$ 가 $(1/6,\ 1/2,\ 1/3)$ 로 **비균등**해져 구현 오류가 드러나고,
- 3번이 **도달 불가능 상태**가 되어 BFS 가지치기의 최소 예제가 되며,
- 특성다항식이 $-\lambda(\lambda-1)(\lambda+1/2)$ 로 깔끔히 인수분해되어
  $|\lambda_2| = 1/2$ 을 손으로 구할 수 있다.

세 성질을 동시에 만족하는 보드를 고른 것이 이 단계에서 한 유일한 설계 판단이다.

검증은 네 경로로 했다. 손계산(유리수 정확 연산) · NumPy 고유벡터 · NumPy 멱승법 ·
몬테카를로 재귀시간. 넷이 모두 일치했고, 오차 감쇠율이 12스텝 내내 0.500000 으로
관측되어 $|\lambda_2|=1/2$ 예측과 맞았다.

**Phase 2 완료 조건(손계산 = NumPy) 충족.** TypeScript 대조는 멱승법이 나오는
Phase 5로 미룬다 — `toy.ts` 에 규칙과 정답을 미리 박아 두었다.

## Phase 3 — 상태공간 확정

43상태를 구현하고 BFS 도달성 검사를 붙였다. 채택안과 버린 안 다섯 가지를
`docs/state-design.md` 에 나란히 적었다.

이 단계에서 한 판단 중 기록할 만한 것 둘.

**기약성은 양방향으로 검사한다.** 정방향 BFS만 돌리면 "출발점에서 모든 상태에 갈 수
있다"만 확인되고 "모든 상태에서 돌아올 수 있다"는 확인되지 않는다. 전이 방향을 뒤집은
그래프에서도 전부 도달 가능해야 강연결이다. 4상태 모델로 이 차이를 테스트했다 —
가지치기 전 행렬은 정방향으로는 3번을 제외한 전부에 닿지만 기약이 아니다.

**우주여행 대기 상태를 만들려다 그만두었다.** 자료에 "우주여행 칸에 도착하면 다음
턴에 이동한다"고 되어 있어 처음에는 상태를 하나 추가할 생각이었다. 그런데 스텝이
턴 단위이므로 "30번에서 턴을 시작한다"는 기존 상태 `c30` 이 이미 그 상황을 정확히
표현한다. 스텝 단위를 턴으로 잡은 결정이 여기서 한 번 더 값을 했다.

## Phase 4 — 전이행렬 생성기

`board.ts`(데이터) → `rules.ts`(칸 효과) → `transition.ts`(턴 전개)로 나눴다.

### 재귀를 버리고 레벨 단위 집계로 바꾼 일

처음에는 더블 재굴림을 그대로 재귀로 짰다. 테스트가 끝나지 않았다.
분기 수를 세어 보니 원인이 분명했다 — 한 번 굴릴 때마다 (주사위 결과 21가지 ×
황금열쇠 카드 30장)이 곱해지고, 더블이면 그 아래로 또 곱해진다. 깊이 3에서 이미
2천만 갈래다.

고친 방법은 **"지금 굴리고 있는 확률질량"을 칸별로 모아 한 레벨씩 밀어내는 것**이다.
같은 칸에 도착한 경로들은 이후 전개가 완전히 같으므로 합쳐도 된다. 깊이당 비용이
40 × 21 × 30 으로 일정해지고 결과는 정확히 같다. 43개 행 전체가 0.1초 안에 나온다.

마르코프 성질(과거를 잊는다)이 계산 구조에 그대로 드러난 지점이다.

### π 와 v 를 한 번에 모으는 이유

한 턴을 전개하면서 전이확률 · 착지 횟수 · 출발선 통과 횟수 · 굴림 수를 함께 모은다.
착지 벡터 $v$ 는 Phase 6의 일이지만, 규칙 전개 코드를 두 벌 두면 반드시 어긋난다.
$\pi$ 와 $v$ 는 **같은 전개에서 나오는 다른 집계**다.

### 테스트가 잡아낸 것 — 두 번 다 테스트가 틀렸다

두 테스트가 실패했는데 둘 다 **내 기댓값이 틀렸고 모델이 맞았다.** 기록해 둔다.

1. `J₀` 의 기대 굴림 수를 1.2 로 적었는데 1.1907 이 나왔다. 순수 순환 보드에서만
   $E[K] = 6/5$ 이고, 실제 보드에서는 무인도나 우주여행에 걸리면 **더블이어도 턴이
   거기서 끝나기** 때문에 그보다 작다. 이 간극이 곧 특수 칸의 효과다.
2. 균등 정책에서 우주여행 칸으로 돌아올 확률을 0으로 적었는데 0.005128 이 나왔다.
   정책이 30번을 목적지에서 제외해도, **황금열쇠 6칸 중 하나에 내린 뒤 우주여행
   초대권(1/30)을 뽑으면** 돌아온다. $6 \times \frac{1}{39} \times \frac{1}{30}
   = 0.005128$ 과 정확히 일치했다.

두 번째는 테스트로 남겼다. 카드 연쇄가 제대로 도는지 확인하는 장치가 된다.

### 해석적 정답 테스트 (§11.2)

특수 칸을 모두 끈 순수 순환 40칸 보드에서 다음을 확인한다.

- $P$ 가 **순환행렬**이다 — 모든 행이 첫 행을 한 칸씩 민 것과 같다
- **열 합도 1**이다 → 이중확률행렬 → $\pi_i = 1/40$ 이 정확히 성립
- $\sum_i v_i = E[K] = 1.2$, 한 턴 기대 이동 거리 $1.2 \times 7 = 8.4$칸
- 턴당 출발선 통과 기대 횟수 $= 8.4/40$

이 테스트 하나가 전이행렬 생성기 버그의 대부분을 잡는다.

### 새로 명시한 가정 A11

"카드로 이동한 뒤 더블 재굴림을 계속하는가"는 규칙서에 없다. 계획서 §3.3의
"더블이면 착지 처리 후 같은 절차를 반복"을 따라 **계속 굴리는 것**으로 정하고
`cardMoveEndsTurn` 플래그로 반대 해석도 실험할 수 있게 남겼다.

## Phase 5 — 정상상태 계산 엔진

멱승법 · 잔차 기록 · 디플레이션 · 로그 회귀를 구현했다. 선형대수는 전부 직접 짰다.

### |λ₂| 가 복소수였다

디플레이션이 수렴하지 않았다. 오차 감쇠비를 찍어 보니 0.63과 0.78 사이를 **규칙적으로
오르내렸다.** 계획서 §15가 미리 적어 둔 "λ₂ 가 복소수여서 디플레이션이 진동" 그대로였다.

NumPy 로 고유값을 직접 구해 확인했다.

$$\lambda_2 = 0.22137214 \pm 0.66826373\,i,\qquad |\lambda_2| = 0.70397588$$

복소 켤레쌍이 회전하기 때문에 **한 스텝의 성장률은 영원히 진동한다.** 그래서
디플레이션을 순간 성장률이 아니라 **성장률의 기하평균** $\|Q^k v\|^{1/k}$ 로 고쳤다.
이 값은 복소수에서도 $|\lambda_2|$ 로 수렴한다.

| 경로 | 값 | 참값과의 차 |
|---|---|---|
| NumPy 고유값 (참값) | 0.70397588 | — |
| 로그 회귀 실측 | 0.70375277 | 0.00022 (R² = 0.999974) |
| 디플레이션 기하평균 | 0.70370216 | 0.00027 |

세 값이 소수 셋째 자리까지 맞는다. 진동 여부는 `oscillating` 으로 따로 보고해
**진동 자체를 복소 고유값의 증거로** 쓴다.

### 계획서 실험 12의 메커니즘을 바로잡았다

계획서는 "주사위를 짝수 눈만 나오게 바꾸면 gcd가 2가 되어 **주기 2**가 생기고 멱승법이
진동한다"고 적었다. 실제로 해 보니 진동하지 않고 **그냥 수렴했다.**

이유를 따져 보니 계획서의 진단이 틀렸다. 주사위 두 개의 눈이 모두 짝수면 합도 모두
짝수이고, 40칸 보드에서 짝수 칸과 홀수 칸이 **서로 오갈 수 없게 된다.** 즉

- 깨지는 것은 **비주기성이 아니라 기약성**이다.
- 체인이 두 개의 닫힌 집합으로 쪼개져 **정상분포가 유일하지 않다.**
- 각 절반 안에서는 이동 거리를 2로 나눈 {2,3,4,5,6} 의 gcd 가 1이라 여전히 비주기다.

실제로 0번에서 시작하면 짝수 칸에만, 1번에서 시작하면 홀수 칸에만 확률이 놓이고,
두 결과의 $\ell_1$ 거리가 2가 된다. 유일성이 깨진 증거다.

**진짜 주기성 데모는 따로 만들었다.** 주사위를 **한 개**로 하고 홀수 눈 {1,3,5}만 쓰면
이동 거리가 모두 홀수가 된다. 40은 짝수이므로 홀수를 짝수 번 더해야만 제자리로
돌아올 수 있고, 따라서 **모든 주기가 짝수 → 주기 2**다. 이때는

- 체인이 **기약이다** (모든 칸에 갈 수 있다)
- 그런데도 멱승법이 수렴하지 않는다
- 홀수 스텝 뒤에는 홀수 칸에만, 짝수 스텝 뒤에는 짝수 칸에만 확률이 놓인다
- 두 스텝을 묶으면($P^2$) 각 절반 안에서 정상적으로 수렴한다

기약성과 비주기성이 **서로 다른 조건**임을 두 데모로 나눠 보일 수 있게 됐다.
`diceCount` 설정을 추가했다.

## Phase 6 — 착지 벡터·보상 엔진

`landing.ts`(v · 월급 통과율) · `payoff.ts`(기대수익 · 회수 지표 · 갱신보상) ·
`hitting.ts`(첫 도달 · Kac)를 붙였다.

### π 와 v 는 정말로 다른 벡터였다

$\pi$ 1위였던 무인도가 $v$ 로는 2위로 내려가고, $v$ 1위는 사회복지기금 수령처가 됐다.
이유가 명확하다 — **무인도에 갇혀 있는 동안 계속 "턴을 시작"하지만 그동안 아무 칸에도
착지하지 않는다.** 반대로 황금열쇠 칸은 $\pi$ 최하위인데 $v$ 로는 중간이다. 착지는
하지만 11/30 확률로 그 자리에서 끌려나간다.

통행료에 $\pi$ 를 쓰면 무인도를 4배 넘게 과대평가한다. 계획 초안의
$\sum_i \pi_i r_i$ 가 왜 틀렸는지가 숫자로 드러났다.

### 자료의 엇갈리던 수치가 전부 풀렸다

계획서 §4.3의 마지막 미해결 항목이던 이스탄불 수익률(240% / 208% / 167.74%)이
**정의 차이**임을 확인했고, 세 값이 우리 표에서 **정확히** 재현됐다.

| 자료의 표현 | 정의 | 값 |
|---|---|---|
| 호텔 가격 대비 240% | 호텔료 ÷ 호텔 건축비 = 60 ÷ 25 | 240.0% |
| 건물 가격 대비 208% | 건물 통행료 합 ÷ 건축비 합 = 104 ÷ 50 | 208.0% |
| 가격 대비 167.74% | 건물 통행료 합 ÷ (매입가 + 건축비) = 104 ÷ 62 | 167.74% |

세 값이 동시에 맞아떨어질 확률은 낮으므로, 이는 **통행료 표 전사가 옳다는 강한 증거**다.
그래서 이 계산을 테스트로 고정했다.

### 테스트가 또 한 번 직관을 꺾었다

"가까운 칸에 먼저 닿을 확률이 더 높다"는 테스트를 썼다가 실패했다.
35번 로마에서 보면 37번 뉴욕은 2칸, 39번 서울은 4칸 앞인데 **서울에 먼저 닿을 확률이
0.596 으로 더 높다.** 주사위 두 개의 합이 2일 확률은 1/36 뿐이고 4일 확률은 3/36 이기
때문이다. 잔여 칸별 도착 확률이 7칸에서 최대가 되는 것과 같은 현상이라
실험 4의 재료로 그대로 쓴다. 테스트는 반대 방향으로 고쳐 남겼다.

### 실험 7이 계획서 예상과 반대로 나왔다

월급 통과율의 근사값은 $8.4/40 = 21\%$ 이고, 계획서는 "무인도 정체와 우주여행 점프
때문에 실제 값은 이보다 **낮을** 것"으로 예상했다. 실제는 **23.462%로 11.7% 더 높았다.**

우주여행 목적지가 균등이면 30번보다 앞 번호로 갈 확률이 높고, 그때 "지구를 한 바퀴
도는 판정"이라 출발선을 지난다. 이동 카드도 출발선을 넘긴다 — 특히 항공여행은
콩코드가 뒤에 있으면 월급을 두 번 받는다. 두 효과가 무인도 정체를 이겼다.

### Kac 검증

선형계로 구한 평균 재귀시간과 멱승법의 $1/\pi_i$ 를 43개 상태 전부에서 비교했다.
최대 상대오차 **2.40 × 10⁻¹⁴**. 두 경로는 공유하는 계산이 전혀 없으므로
서로를 검증한다. (§11.4 세 번째 축)

## Phase 7 — 몬테카를로 엔진

규칙 정의는 공유하되 계산 경로를 완전히 분리했다. `transition.ts` 가 확률을 모아

### 시뮬레이션이 해석해의 버그를 잡았다

월급 통과율이 시뮬레이션 24.026%, 해석해 23.462% 로 어긋났다. 720,000턴을 돌렸으므로
표준오차는 0.05%p 남짓인데 차이가 0.56%p 였다 — 노이즈가 아니었다.

차이의 크기가 힌트였다. 황금열쇠 칸 여섯 개의 $v$ 합이 턴당 약 0.168 이고, 카드 한
장을 뽑을 확률이 1/30 이니 $0.168/30 = 0.0056$. **정확히 0.56%p.** 카드 한 장을
빠뜨린 것이다.

범인은 **세계일주 초대권**이었다. 이 카드는 위치를 바꾸지 않으므로 `expandCard` 의
"위치를 바꾸지 않는 카드" 분기로 빠졌고, 거기서 `salaryPasses: 0` 을 반환하고 있었다.
그런데 세계일주는 **제자리인데도 한 바퀴를 돈 것으로 쳐서 월급을 받는다.**
위치 과정만 보면 아무 일도 없는 카드라 놓치기 쉬운 자리였다.

고치자 24.018% 로 시뮬레이션과 맞았다. 두 경로를 분리해 둔 것이 그대로 값을 했다.
회귀 테스트로 박아 두었다.

### 다중 독립 체인

한 체인을 길게 돌리면 연속 표본이 상관되어 $\sqrt{\pi(1-\pi)/N}$ 로 만든 신뢰구간이
과소평가된다. 그래서 독립 체인을 여러 개 돌리고 **체인 간 분산**으로 구간을 만들었다.
400체인 × 1800턴에서 40칸 중 38칸이 95% 구간 안에 들어왔다 — 95% 구간의 기대값과 같다.

### 실험 11 — 정량적 결론

체인 수를 4에서 512까지 늘리며 $\|\hat\pi - \pi\|_1$ 을 로그–로그로 그렸다.
기울기 **−0.5194** (이론값 −0.5). "줄어든다"가 아니라 "$O(N^{-1/2})$ 로 줄어든다".

### 실험 6 — 갱신보상 근사가 정당했다

사회복지기금 적립액 분포를 실측했다. 가장 흔한 결과는 **빈 손(56.23%)** 이고,
45만 원 이상은 **5.71%** 다. 통설("45만 원 이상은 거의 없다")과 방향이 맞지만
"거의 없다"보다는 조금 있다.

평균 수령액이 시뮬레이션 10.277만, 갱신보상 근사 10.165만으로 1.1% 안에서 맞았다.
잔액을 상태에 넣지 않은 가정 A10 이 정당함을 보인 셈이다.

### 가정 A5(복원 추출)의 영향

복원과 비복원을 같은 씨앗으로 각각 돌렸다. $\ell_1$ 차이가 몬테카를로 오차 수준이라
근사가 정당하다.

## 실험 8 — 유입 경로 계측

칸별로 "어떤 경로로 들어왔는가"를 전이행렬 생성 중에 함께 세도록 계측을 붙였다.
`InflowSource` 는 주사위 · 이동 카드 · '이사' 뒤로 · 우주여행 네 가지로 시작했는데,
합이 $\pi$ 와 맞지 않아 테스트가 깨졌다. 무인도만 어긋났다.

원인은 **무인도 대기 중 J₃ → J₂ 같은 전이가 '유입'이 아니라는 것**이었다.
새로 들어온 것이 아니라 계속 갇혀 있는 몫이다. `stay` 를 다섯 번째 경로로 추가하니
다섯 경로의 합이 모든 칸에서 $\pi$ 와 정확히 맞았다.

이 구분이 곧 결과였다. **무인도 π 10.835% 중 67.8%가 체류**이고 새로 들어오는 몫은
3.49% 뿐이다. "무인도가 왜 높은가"의 답은 "잘 들어가서"가 아니라 "못 나와서"다.

실험 9와도 맞물린다. 뭉갠 모델이 무인도 확률을 1.76배로 부풀린 것은 체류 시간을
6턴으로 잘못 잡았기 때문인데, **체류가 지배적 성분이므로 그것을 틀리면 통째로 틀어진다.**

서울 쪽에서는 다른 것이 보였다. 주사위만으로 본 서울 방문 확률은 1.902%로 균등(2.5%)
보다 **낮다.** 39번이 출발에서 가장 먼 칸이기 때문이다. 카드(18.6%)와 우주여행(3.4%)이
없었다면 서울은 오히려 잘 안 걸리는 칸이었을 것이다.

### 색을 마지막에 정했다

크기를 나타내는 값(π · v · 전이확률)에는 **파랑 한 색의 명도 램프**를 쓰고,
서로 다른 것을 구분하는 값(수렴 곡선 3종, 유입 경로 5종)에는 **고정 순서의 범주
슬롯**을 쓴다. 무지개색은 쓰지 않았다.

색맹 판별 가능성은 눈으로 보지 않고 검증기를 돌려 확인했다. 수렴 곡선 3색은
all-pairs 기준으로, 유입 경로 5색은 인접쌍 기준(누적 막대)으로 모두 통과했다.
대비가 3:1에 못 미치는 슬롯이 있어 **범례와 직접 라벨을 반드시 함께** 실었다.

## Phase 8-b — 정적 빌드를 브라우저에서 실제로 굴려 보기

배포 전에 `npm run build` 산출물을 정적으로 서빙하고 Playwright 로 **직접 조작**했다.
테스트 126개가 전부 통과하는 상태였는데도 **버그 세 개**가 나왔다. 셋 다 계산이 아니라
화면 쪽이라 단위 테스트가 잡을 수 없는 것들이었다.

### 1. 툴팁이 앱을 죽였다 (React error #185)

칸에 마우스를 올리는 순간 무한 렌더 루프가 났다. 툴팁이 화면 밖으로 나가지 않게
크기를 재려고 `ref` 콜백에서 `setSize` 를 불렀는데, **ref 콜백은 렌더마다 실행되고
`setSize` 는 매번 새 객체를 만드니** 렌더 → setState → 렌더가 끝없이 돌았다.

배포했다면 **아무 칸에나 마우스를 올리는 순간 앱이 하얗게 죽었을 것**이다.
스크린샷만 찍었을 때는 마우스를 움직이지 않아 드러나지 않았다.

고친 방법은 측정을 없애는 것이다. 포인터가 화면의 어느 사분면에 있는지만 보고 CSS
`transform` 으로 뒤집는다. 측정도 상태도 없으니 루프가 생길 수 없다.

### 2. 실험 12 데모 설정이 앱을 죽였다

'기약성 파괴'(짝수 눈)를 고르면 예외가 나면서 화면이 사라졌다. 기약이 아닌 체인에서는
첫 도달 시간 선형계 $(I-Q_A)h=\mathbf 1$ 이 **특이행렬**이라 가우스 소거가 던진다.

**조건을 깨뜨리는 것이 목적인 데모가 앱을 죽이면 안 된다.** 기약성과 수렴 여부를 먼저
확인하고, 깨졌으면 Kac 검증을 건너뛴 뒤 **무엇이 왜 깨졌는지 화면에 설명한다.**
결과적으로 오히려 좋은 교보재가 됐다 — 배너가 "정상분포가 유일하지 않고 초기 분포에
따라 다른 곳으로 수렴한다"고 말해 주고, 히트맵에는 5.000% 와 0.000% 가 번갈아 뜬다.

같은 맥락에서 파생값이 `Infinity`·`NaN` 으로 새어 나오던 것도 막았다. 정상분포가
아니면 $v$ 도 월급 통과율도 뜻이 없으므로 줄표로 둔다.

### 3. 주사위 설정만으로는 주기성이 생기지 않았다

설정 패널의 "1개 · 홀수만 → 주기 2" 를 골라도 $|\lambda_2| = 0.894$ 가 나왔다.
황금열쇠·우주여행·무인도가 켜져 있으면 홀짝 구조가 깨지기 때문이다. **여러 설정이
함께 맞아야 성립하는 조합인데 패널이 그걸 알려 주지 못했다.**

**실험 프리셋** 여섯 개를 넣었다. 누르면 필요한 설정이 한꺼번에 맞춰진다.
'주기 2' 프리셋에서 $|\lambda_2| = 1.0000$, 잔차 2.0, 5000회 반복 뒤에도 수렴하지 않고,
수렴 그래프의 오차 곡선이 **톱니처럼 진동하며 영영 줄지 않는다.** 실험 12가 화면
하나로 끝난다.

### 그 밖에

- `/favicon.ico` 404 → data URI SVG 아이콘을 인라인으로 넣었다.
- CSS 에 `prefers-color-scheme` 미디어 쿼리만 있고 **명시적 `[data-theme="dark"]`
  블록이 없었다.** 뷰어가 다크를 직접 고르면 토큰이 적용되지 않아 어두운 바탕에
  검은 글씨가 나왔을 것이다. 두 블록을 모두 두었다.
- `history.replaceState` 를 try/catch 로 감쌌다. 임베드 환경에서 막혀도 앱이 죽지 않는다.
- 좁은 화면(430px)에서 가로 넘침 0px 확인.
